## 1. Hit-registration architectures (client raycast + server validation, lag compensation/rewind, FastCast, projectile vs hitscan) and expert recommendations

### Takeaway
The standard 2026 pattern is still **client-authoritative aiming with server validation**. The client raycasts from its camera and sends the shot to the server. The server re-derives what it can and runs sanity checks: origin distance, angle/spread tolerance, rate of fire, target near the claimed hit point, line of sight. Roblox's own Laser Tag/FPS templates use exactly this. For stricter competitive play, the community has open-source **server-side rewind** frameworks (RollbackHitbox, RollbackService; Rewind and SecureCast are now archived). Roblox's new **Server Authority** model (fully released 2026) covers movement and physics but **does not solve hit detection**. Roblox explicitly calls shooting mispredictions normal and says time-synced/rollback-aware events are still being explored.

### Cited Findings
**Roblox's official reference implementation (Laser Tag / FPS System templates)**
- The client builds the shot from `currentCamera.CFrame.Position` plus per-blaster spread directions (`getDirectionsForBlast`) and calls `Workspace:Raycast()`, excluding the shooter's character. It then sends `rayResults` (destination CFrame plus tagged Player or nil) to the server via a RemoteEvent. — [Roblox Docs: Detect hits](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/detect-hits)
- Server validation chain in `getValidatedRayResults`: (1) type-check each entry (CFrame and Player/nil); (2) `isRayAngleFromOriginValid`: the server calls the same shared `getDirectionsForBlast` and compares angles against `BLAST_ANGLE_SANITY_CHECK_TOLERANCE_DEGREES`; (3) `isPlayerNearPosition`: the tagged player's `GetPivot()` must be within `DISTANCE_SANITY_CHECK_TOLERANCE_STUDS` of the claimed hit point; (4) `isRayPathObstructed`: a server raycast checks for walls between origin and destination, which defeats clients that delete walls locally. — [Roblox Docs: Detect hits](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/detect-hits)
- The origin check (`getValidatedBlastData`) verifies the shooter's character was near the claimed origin. Roblox calls the tolerance "a judgment call" that depends on server latency and movement speed, and says to raise it if you increase movement speed. — [Roblox Docs: Implement blasters](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/implement-blasters)
- Fire-rate cooldown (`secondsBetweenBlasts`) runs on both client and server, "with the server acting as the source of truth". Damage is stored server-side as a blaster attribute (`damagePerHit`), not sent by the client. — [Roblox Docs: Implement blasters](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/implement-blasters); [Detect hits](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/detect-hits)
- Roblox security docs: the client should send "the origin position of the shot and the part/position it thinks it has hit", not "who to damage". The server should also "track when the player last fired their weapon and validate to ensure they're not shooting too fast". — [Roblox Docs: Securing the client-server boundary](https://create.roblox.com/docs/scripting/security/client-server-boundary)
- `Raycast()` does not respect `CanCollide` by default; use `RaycastParams.RespectCanCollide` for decorative parts. `RaycastResult.Material` can drive armor/weak-point damage and `Distance` can drive damage falloff. — [Roblox Docs: Detect hits](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/detect-hits)

**Server Authority and hit detection (official, 2026)**
- Server Authority docs do **not** cover hit detection, shooting, or lag compensation. The Laser Tag server-authority sample reportedly kept its shooting code unchanged. Remote events are not time-synced with the client simulation (reportedly about 40–50 ms off), which produces mispredictions Roblox calls normal for shooters. Roblox says it is investigating time-synced / rollback-aware event APIs. — [Roblox Docs: Server authority model](https://create.roblox.com/docs/projects/server-authority); [DevForum: Full Release BindToSimulation](https://devforum.roblox.com/t/full-release-bindtosimulation-rolling-out-usefixedsimulation/4605516) and [Server Authority Studio Beta – Insights from Engineers](https://devforum.roblox.com/t/server-authority-studio-beta-insights-from-engineers/4139321) (search-summary only)
- Remote events "might not be consistently ordered with property and attribute updates over the network", so don't assume a shot remote arrives in order with state changes. — [Roblox Docs: Server authority model](https://create.roblox.com/docs/projects/server-authority)

**Community lag-compensation / rewind frameworks**
- **RollbackHitbox** (open source): every Heartbeat it stores hitbox positions in a ring buffer. On a shot it rewinds registered characters' hitboxes to the shot timestamp, and **clamps the rewind window** so clients can't claim arbitrarily old positions. The author says it validates geometric plausibility only and **does not stop aimbots**. — [DevForum: RollbackHitbox](https://devforum.roblox.com/t/rollbackhitbox-server-authoritative-lag-compensation-for-roblox-shooters-open-source/4553295) (search-summary)
- **RollbackService** is a general "time machine" state-history service with lag-compensated hit reg as one use case, designed to pair with native Server Authority. — [DevForum: RollbackService](https://devforum.roblox.com/t/resource-rollbackservice-the-time-machine-for-server-authority-state-validation/4200068) (search-summary)
- **Rewind** ("Server validates all hits – client can't cheat") added custom character replication in v1.1 and had hit-priority profiles and a state buffer. It is now marked **[Archived]**. I could not find the reason. — [DevForum: Rewind (archived)](https://devforum.roblox.com/t/archived-rewind-server-authoritative-hit-validation-custom-character-replication/4160622) (search-summary)
- **SecureCast** (server-authoritative projectiles with lag compensation and multithreading) is also **[ARCHIVED]**. — [DevForum: SecureCast](https://devforum.roblox.com/t/archived-securecast-server-authoritative-projectiles-with-lag-compensation-multi-threading-and-more/2546164)
- Skeptic view: one developer who built lag compensation says "don't waste your time making a lag compensation system using the roblox engine, unless you are going to use it for large hitbox detections", citing engine inaccuracy. They suggest custom replication makes it more reliable. A 2021 thread says lag compensation is "no better than properly setting up client sided hit registration and validating it on the server". — [DevForum: Lag compensation is inaccurate](https://devforum.roblox.com/t/lag-compensation-is-inaccurate/1419968) (search-summary, older)
- Older consensus (2019): use client-side hit detection for UI feedback with full server damage checks. The hit event "isn't secure without checking the distance between the player's character and the player who the character is claiming to hit". — [DevForum: Laggy players can't register hits](https://devforum.roblox.com/t/laggy-players-cant-register-weapon-hits-best-way-to-get-around-without-trusting-the-client/377314) (search-summary)
- Server-side hit detection makes the shooter's world state lag behind, so it "can feel clunky and unresponsive". This is why client detection plus server checks dominates. — [DevForum: My weapons use client-sided hit detection…](https://devforum.roblox.com/t/my-weapons-use-client-sided-hit-detection-how-should-i-go-about-securing-them-on-the-server/2644473) (search-summary)

**Projectiles: FastCast and successors**
- FastCast (2018) is not officially deprecated, but a Sept 2025 thread calls it "a pretty outdated module by 2025 Luau standards" and recommends plain raycasting. — [DevForum: Alternatives for Fastcast?](https://devforum.roblox.com/t/alternatives-for-fastcast/3182754) (search-summary); original: [DevForum: FastCast](https://devforum.roblox.com/t/making-a-combat-game-with-ranged-weapons-fastcast-may-be-the-module-for-you/133474)
- **FastCast2**: a successor with Parallel Luau, static typing and more extensions. The author says it handles 100+ projectiles more efficiently (posted about late 2025). — [DevForum: FastCast2](https://devforum.roblox.com/t/fastcast2-an-improved-version-of-fastcast-with-parallel-scripting-more-extensions-and-statically-typed-a-powerful-modern-projectile-library/4093890) (search-summary)
- **SimpleCast**: lighter, with a built-in projectile cache and its own physics. **Flashcast**: a 3.0 rewrite, but a commenter says it's unmaintained. — [DevForum: SimpleCast](https://devforum.roblox.com/t/simplecast-an-alternative-to-fastcast/2271321); [DevForum: Flashcast](https://devforum.roblox.com/t/flashcast-a-fine-grained-alternative-to-fastcast/2947871) (search-summary)
- Reported FastCast issues: jitter with model/mesh cosmetic bullets and inaccurate hit detection. A server-side FastCast hit-reg delay thread also exists. — [DevForum: FastCast laggy with projectile models](https://devforum.roblox.com/t/fastcast-laggy-with-projectile-models/2869465); [DevForum: FastCast server hit reg delay](https://devforum.roblox.com/t/fastcast-server-hit-reg-delay/2846684)
- Roblox's own prefab Weapons Kit is **projectile-based**. Setting `ShotSpeed` very high (e.g. `20000`) "simulates raycasting weapons". Gravity factor, MaxDistance, Min/MaxSpread, NumProjectiles (shotguns), and recoil params are all config attributes. — [Roblox Docs: Weapons kit](https://create.roblox.com/docs/resources/weapons-kit)

**Networking primitives relevant to shot traffic**
- `UnreliableRemoteEvent`: unordered and unreliable, "best used for ephemeral events" such as effects and continuously changing data. Payloads **over 1000 bytes are dropped**. RemoteEvent and UnreliableRemoteEvent each have a **~500 requests/sec per client** limit shared among all remotes of that type. — [Roblox Docs: UnreliableRemoteEvent](https://create.roblox.com/docs/reference/engine/classes/UnreliableRemoteEvent)
- `Workspace:GetServerTimeNow()` returns the client's smoothed estimate of server Unix time. It is monotonic and within 0.6% of the local clock rate, and Roblox says it is "not secure" for timed rewards. Under Server Authority, use `time()` in simulation code (synced, fixed-step, rewinds during resim). — [Roblox Docs: Workspace.GetServerTimeNow](https://create.roblox.com/docs/reference/engine/classes/Workspace); [Server authority model](https://create.roblox.com/docs/projects/server-authority)

### Inferences
- **Recommended baseline for a small-arena 1v1–3v3 game:** hitscan for most guns. The client raycasts from the camera and sends `{shotId, clientServerTime (GetServerTimeNow), origin, direction(s), claimed hit part, claimed hit position}` on a reliable RemoteEvent. Use a single shot remote and keep payloads compact; `buffer` packing helps if bandwidth matters. The server checks types/NaN, fire rate via its own ammo and cooldown state, origin distance, angle versus server-regenerated spread (use a seeded RNG on both sides, as Laser Tag does), then line of sight, then a **rewound** target-position check. That last one is a ring buffer of each character's hitbox CFrames at Heartbeat; look up the target at `clamp(clientTime, now - MAX_REWIND, now)` with MAX_REWIND around 200–250 ms and test the claimed hit point against an inflated hitbox. This is the RollbackHitbox approach without full server re-raycasting against rewound geometry, so it stays cheap.
- Small arenas and 6 or fewer players make per-shot server rewind computationally trivial. The main cost is tuning tolerances so high-ping players aren't rejected. Log rejections per player (a suspicion score, see §3) rather than silently dropping, so you can tune.
- Use projectiles (FastCast2, or a custom parabola stepped in Heartbeat/BindToSimulation) only for weapons/abilities where travel time is a gameplay feature, such as rockets, grenades or bows. For those, the Server Authority "predictive instance creation" path (§3) is now the official way to avoid pop-in.
- Archived rewind libraries (Rewind, SecureCast) suggest maintainers moved on after Server Authority. That last part is unverified. Treat community libraries as reference designs and own the code.
- Expect Roblox to ship time-synced or rollback-aware events eventually. Design the shot pipeline so the transport can be swapped later.

### Gaps
- No primary source for Roblox's exact remote-event-vs-simulation timing offset; "40–50 ms" comes from a search summary of an engineer Q&A.
- Why Rewind was archived is unknown.
- No benchmark data comparing rewind accuracy on Roblox's default character replication (interpolation delay is not documented publicly in what I found).

### Takeaway
**There is essentially no public, authoritative technical documentation** of RIVALS', Phantom Forces' or Bad Business' netcode. What exists is forum hearsay (e.g. "Phantom Forces does a server distance check then server ray") and exploit-vendor pages advertising "silent aim". Silent aim implies these games accept client-reported hit/aim data to some degree.

A fan wiki lists "Sensei Warrior" as co-owner/lead programmer (unofficial). — [Roblox: RIVALS game page](https://www.roblox.com/games/17625359962/RIVALS); [rivalsroblox.wiki developers (fan site)](https://rivalsroblox.wiki/community/developers/)
- I found no source describing RIVALS' hit registration or netcode. — (search returned only code/guide sites)

This is unverified and not from the developers. — [DevForum: FPS anti exploits?](https://devforum.roblox.com/t/fps-anti-exploits/212634) (search-summary, ~2018)

### Inferences
- RIVALS is the closest analogue to the user's design (short-round duels, small maps, cross-platform). Its reported features (mobile aim assist, controller support) suggest that Roblox's competitive shooter audience expects aim assist on touch and gamepad.
- Silent aim works against any game whose server accepts a client's claimed hit part or direction while only checking plausibility. Server checks narrow it (LOS, FOV/angle-vs-camera-history checks) but cannot eliminate it. See §3.

## 3. Common exploits, server-side mitigations, Hyperion status, and Roblox Server Authority

### Takeaway
Roblox's official position (security docs rewritten Sept 2025, kept current in 2026) is "never trust the client". Use validation, rate limiting and server-side heuristics with a suspicion score, never client-side ban triggers. **Server Authority is now generally available (mid-2026)**. It moves character movement and physics to the server with client prediction and rollback, which closes speed, fly, teleport and fling hacks with little custom code. It does **not** stop aimbot or silent aim. Hyperion (Byfron) still raises the bar on Windows desktop, but there is no official 2026 status post and its coverage on mobile, Mac and console is unconfirmed.

### Cited Findings
**What exploiters can do (official list)**
- Exploiters can decompile any replicated LocalScript/ModuleScript; take network ownership of their character and nearby unanchored parts; fire Touched/ProximityPrompt at any range; modify position and physics; fire remotes "at any frequency with arbitrary arguments"; and change their local DataModel silently. — [Roblox Docs: Security tactics](https://create.roblox.com/docs/scripting/security/security-tactics)
- With network ownership they can teleport, set any WalkSpeed (not observable from LocalScripts), play arbitrary animations, noclip, send `Inf`/`NaN` CFrames and velocities to fling others, and suppress or forge Touched. — [Roblox Docs: Network ownership & movement validation](https://create.roblox.com/docs/scripting/security/network-ownership)
- `NaN` passes `typeof(x)=="number"` and fails every comparison, so it bypasses range checks. Reject with `math.isfinite()`. — [Roblox Docs: Client-server boundary](https://create.roblox.com/docs/scripting/security/client-server-boundary)
- Rate-limit everything client-triggerable. The docs recommend a **token bucket**. — [Roblox Docs: Client-server boundary](https://create.roblox.com/docs/scripting/security/client-server-boundary)

**Detection and consequences (official)**
- "The server decides… Try to never ban based on client-side detections." Quietly neutralize first (e.g. rubber-band speedhackers). Be proportional and reversible. "Design > detection." — [Roblox Docs: Server-side detection](https://create.roblox.com/docs/scripting/security/server-side-detection)
- Heuristics: theoretical-max checks, **rate-of-gain**, and **action cadence** (robotic, identical inter-action intervals indicate macros). Use a **suspicion score** that only acts after multiple varied signals. — [Roblox Docs: Server-side detection](https://create.roblox.com/docs/scripting/security/server-side-detection)
- **Honeypot remotes** (never fired by legit code means an exploiter, so log and kick). Also direction-tracking: firing a server-to-client remote from the client is a reliable flag. — [Roblox Docs: Server-side detection](https://create.roblox.com/docs/scripting/security/server-side-detection)
- Consequence ladder: silent logging, then quiet mitigation, then temporary restrictions (e.g. matchmaking), then visible enforcement. Delay visible consequences so cheaters can't learn triggers. Use `Players:BanAsync` (Ban API) for persistent offenders. — [Roblox Docs: Server-side detection](https://create.roblox.com/docs/scripting/security/server-side-detection)
- Movement validation without Server Authority: simple distance-over-time "may suffice for competitive shooters". Use leaky-bucket accumulators for bursts, project onto the XZ plane, and add explicit exemptions for legit teleports/dashes. — [Roblox Docs: Network ownership](https://create.roblox.com/docs/scripting/security/network-ownership)
- The security docs were comprehensively rewritten in an announcement dated Sept 26, 2025. Roblox said it would keep updating them, including for Server Authority. — [DevForum: Security Tactics and Cheat Mitigation Docs Update](https://devforum.roblox.com/t/security-tactics-and-cheat-mitigation-docs-update/3959613) (search-summary)

**Server Authority (Roblox's built-in authority/prediction/rollback)**
- Timeline: on the Spring 2025 roadmap, part of a broader effort reportedly called "Aurora" that includes rollback netcode. Studio Beta (late 2025), then Client Beta / publishable on April 30, 2026, then **Full Release** ("Ship Fair And Competitive Games with Server Authority"). Roblox on X: "Server Authority is now available for all creators. Block physics-based exploits like speed hacks without custom anti-cheat code, while prediction and rollback help preserve a responsive player experience." A Roblox newsroom post is dated July 2026. — [DevForum: Full Release](https://devforum.roblox.com/t/full-release-ship-fair-and-competitive-games-with-server-authority/4727993); [DevForum: Client Beta](https://devforum.roblox.com/t/client-beta-publish-test-your-server-authoritative-experiences/4606949); [Roblox on X](https://x.com/Roblox/status/2075267517111582783); [Roblox Newsroom (Jul 2026)](https://about.roblox.com/newsroom/2026/07/creating-responsive-cheat-resistant-games-roblox-server-authority); [Creator Roadmap Spring 2025](https://devforum.roblox.com/t/creator-roadmap-2025-spring-update/3624895?page=5) (all search-summary; the exact full-release day was not confirmed)
- **Docs conflict:** the network-ownership security page (still live Oct 2026) says Server Authority "is currently in beta and will be released soon". The page is stale relative to the full-release announcement. — [Roblox Docs: Network ownership](https://create.roblox.com/docs/scripting/security/network-ownership)
- Model: the server is "the single source of truth for the entire game state". Clients send only inputs, predict a few frames ahead, and on misprediction roll back to server state and resimulate. "Mispredictions are a normal and expected part of the server authority architecture." — [Roblox Docs: Server authority model](https://create.roblox.com/docs/projects/server-authority)
- Required Workspace settings: `AuthorityMode = Server`, `NextGenerationReplication`, `PlayerScriptsUseInputActionSystem`, `SignalBehavior = Deferred`, `UseFixedSimulation`, and `StreamingEnabled`. — [Roblox Docs: Server authority model](https://create.roblox.com/docs/projects/server-authority)
- Core logic goes in `RunService:BindToSimulation()` inside a ModuleScript loaded on both client and server. Only "Simulation Access" APIs are allowed there. Use `time()`, not `tick()`/`os.clock()`. Use `InputActions` (not `UserInputService.InputBegan`) for simulation inputs. Sync custom state through **attributes**: only the first 64 replicate, names are 50 characters max, string values 50 characters max, and a mismatch triggers a full rollback. `RunService:SetPredictionMode()` gives finer control. — [Roblox Docs: Server authority model](https://create.roblox.com/docs/projects/server-authority)
- VFX, sound and animation must **not** run in bound functions. Render from `RenderStepped` and be ready to "undo" mispredicted effects. Drive effects from attribute state machines (e.g. grenade Idle/Lit/Exploded). **Predictive instance creation** gives rockets and projectiles deterministic GUIDs so the client copy merges with the server's, with no pop-in. Use `TweenService:SmoothDamp` clones to smooth corrections. Cached `AnimationTrack`s go stale after rollback, so look tracks up by ID. Designing in latency (fuses, slower acceleration) hides resims. — [Roblox Docs: Server authority techniques](https://create.roblox.com/docs/projects/server-authority/techniques)
- Other players' inputs are not forwarded by default (remote players can look laggy). The Racing template stores inputs in attributes. Debug with the Server Authority visualizer (Ctrl/Cmd+Shift+F6): prediction success rate, input accept rate, step delta; server heartbeat below 59 means the server can't keep up. — [Roblox Docs: Server authority techniques](https://create.roblox.com/docs/projects/server-authority/techniques)
- Beta-era known issues: no rollback event for resetting custom state, and input signals/Touched inaccurate during rollback (workarounds: poll input in the callback, use `GetTouchingParts`). Whether these are fixed at full release is unconfirmed. — [DevForum: Full Release BindToSimulation](https://devforum.roblox.com/t/full-release-bindtosimulation-rolling-out-usefixedsimulation/4605516) (search-summary)
- Server Authority is opt-in. Templates: Racing, Soccer, Laser Tag. — [Roblox Docs: Server authority model](https://create.roblox.com/docs/projects/server-authority); [DevForum: Studio Beta](https://devforum.roblox.com/t/studio-beta-build-fair-responsive-games-with-server-authority/4139157)

**Hyperion / Byfron (client anti-tamper)**
- No official 2026 Hyperion status post was found. Community reports conflict: one DevForum claim says ban waves were replaced by easily bypassed "client modification" bans, while others say waves continue. A third-party guide says waves come roughly every 3 months. — [DevForum: Exploit Prevention Update p.68](https://devforum.roblox.com/t/exploit-prevention-update/2663101?page=68); [robloxinject guide (exploit-adjacent, low reliability)](https://robloxinject.com/guides/how-to-avoid-ban-waves/)
- March 2026 bug report: Hyperion reportedly flags developers testing their own anticheats in games they have edit rights to. — [DevForum: Hyperion incorrectly bans developers](https://devforum.roblox.com/t/hyperion-incorrectly-bans-developers-for-permitted-anticheat-testing-on-edit-enabled-experiences/4527239) (search-summary)
- Roblox tightened its policy on third-party emulators (account farming/exploits). Commenters say this hampers emulator-based Hyperion bypasses. — [DevForum: An Update on Using Third-Party Emulators](https://devforum.roblox.com/t/an-update-on-using-third-party-emulators/3867040?page=2)
- A commentary site says exploiting is "far harder and far less reliable than before Hyperion" and paid tools survive days to weeks between updates. This is secondary and unverified. — [Endsights: Roblox anti-cheat in 2026](https://endsights.com/roblox-anti-cheat)
- Hyperion's coverage on mobile, Mac and console is unconfirmed. A DevForum user speculates it's PC-only. An executor vendor claims mobile and Mac "would follow". Neither is reliable. — [DevForum: Security docs update p.4](https://devforum.roblox.com/t/security-tactics-and-cheat-mitigation-docs-update/3959613?page=4); [deltaexecutor timeline (vendor, low reliability)](https://deltaexecutor.co/learn/byfron-vs-hyperion-timeline)

**Gun kit security**
- ACS reportedly had a public "kill all" exploit. Carbon Engine and Alpha Engine are considered harder to exploit but are obfuscated, which makes them hard to audit or edit. — [DevForum: Best weapon systems for a game with a lot of shooting?](https://devforum.roblox.com/t/what-are-the-best-weapon-systems-preferably-fe-for-a-game-with-a-lot-of-shooting/2716544); [DevForum: Is there any usable user-friendly fps frameworks?](https://devforum.roblox.com/t/is-there-any-usable-user-friendly-fps-frameworkssystems/2153442) (search-summary)

### Inferences
- **Exploit-to-mitigation map for this game:**
  - *Speed, fly, teleport, noclip, fling:* enable Server Authority. Small arenas and few players suit it, though it forces IAS, StreamingEnabled and deferred signals from day one. Fallback is XZ leaky-bucket movement validation.
  - *Remote spam / rapid fire:* token bucket per remote plus server-owned ammo, cooldown and fire-rate state; drop excess shots silently.
  - *Wallhack shots:* server LOS raycast against server geometry.
  - *Hitbox expander / fake hit part:* verify the claimed hit position against the rewound, inflated server hitbox.
  - *Silent aim:* check the shot direction against the client's recently reported camera look vector (send a low-rate camera CFrame on an UnreliableRemoteEvent). A hit that arrives with no matching aim history is a flag.
  - *Aimbot:* cannot be prevented server-side. Use statistical heuristics: headshot % versus population, snap angular velocity before kills, time-to-kill distribution, cadence. Feed them into a suspicion score, then use temporary matchmaking restrictions and manual review/replays before `BanAsync`.
  - *ESP:* limit what replicates (StreamingEnabled helps; don't replicate hidden-ability state like invisibility to enemy clients).
  - *Honeypot remotes:* cheap, high-confidence.
- Don't rely on Hyperion. Most Roblox players are on mobile (see §5) and Hyperion's coverage there is unknown.
- Ability drafting adds attack surface. Every ability needs the same validation: server-owned cooldowns, range and LOS checks, and server-side effect resolution.

### Gaps
- No official Hyperion 2025–2026 status or platform-coverage statement found.
- No public data on how much Server Authority reduces cheating in shipped games (the newsroom page couldn't be fetched).
- Whether Server Authority's full release resolved the beta known issues is unknown.

## 4. Game feel: viewmodels, recoil, camera shake, hit markers, sound, kill feed; frameworks (ACS, Carbon Engine, FE Gun Kit)

### Takeaway
Gun feel on Roblox is built client-side and immediately: a camera-attached viewmodel, spring-driven recoil and sway, separate camera kick versus visual shake, instant local muzzle flash, tracer and hit marker, and server-confirmed damage numbers and kill feed. Existing kits (ACS, Carbon Engine, FE Gun Kit) are aimed at milsim or arcade casual play and carry security and maintainability baggage. **For a competitive ability-draft game, build a custom framework.** Use Roblox's open Laser Tag/FPS System template (and its Aim Assist module) as reference code.

### Cited Findings
- The classic "FPS using ViewModels (improved)" tutorial covers ADS and spring recoil, but its author has stopped supporting it and points to an EgoMoose tutorial instead. — [DevForum: FPS using ViewModels pt 2](https://devforum.roblox.com/t/fps-using-viewmodels-the-improved-version-parts-2-out-of-3/1129877) (search-summary)
- Spring-based recoil applied to the **viewmodel CFrame** rather than the camera is a common approach. A simpler alternative keeps an accumulated recoil CFrame, adds to it per shot, and lerps it back to identity each frame. — [DevForum: Recoil using springs](https://devforum.roblox.com/t/recoil-using-springs/1495471); [DevForum: How to make gun recoil/Camera shake?](https://devforum.roblox.com/t/how-to-make-gun-recoilcamera-shake/1183407) (search-summary)
- Pitfall: spring-applied camera recoil causes glitches when firing straight up (gimbal and pitch-clamp issues). — [DevForum: Players camera glitches when shooting upwards](https://devforum.roblox.com/t/players-camera-glitches-when-shooting-upwards/2710809)
- Separate the "visual shake that mouse movement can't cancel" from aim-moving recoil. — [DevForum: Need help adding visual recoil (camera shake)](https://devforum.roblox.com/t/need-help-adding-visual-recoil-camera-shake-how/3904950)
- Roblox Weapons Kit recoil parameters, a useful tuning vocabulary: `RecoilMin`/`RecoilMax` per shot, `TotalRecoilMax` cap, `RecoilDecay`, `RecoilDelayTime`, and `MinSpread`/`MaxSpread`. Effects include Beam0/Beam1 tracers, TrailParticles, HitEffect/HitSound/HitParticles, bullet-hole HitMarks with `AlignHitMarkToNormal`, and a GUI that shows spread and hit indicators. — [Roblox Docs: Weapons kit](https://create.roblox.com/docs/resources/weapons-kit)
- Laser Tag template separates `FirstPersonBlasterVisuals` (client: blast animation, cooldown bar, fired via a local BindableEvent) from `ThirdPersonBlasterVisuals` (server-side) and a `SoundHandler`. The template exposes damage, ammo, recoil and spread attributes. The **FPS System** template contains the same blaster system plus practice targets. — [Roblox Docs: Implement blasters](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/implement-blasters); [Roblox Docs: Templates](https://create.roblox.com/docs/resources/templates)
- Fire on input **Begin**, not End. Roblox's tutorial demonstrates that firing on release feels worse. — [Roblox Docs: Implement blasters](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/implement-blasters)
- Thicker projectiles plus aim assist made combat feel "a lot more fluid" (top-down shooter thread, older). — [DevForum: Aim assist or bullet magnetism](https://devforum.roblox.com/t/aim-assist-or-bullet-magnetism-for-quarter-view-top-down-shooter/429641)
- **Framework comparison (DevForum opinion, mostly 2023 era):**
  - *ACS* is "much better fitted for semi-realistic games", with medical, melee and modding, but is "very prone to exploiters (theres a kill all exploit)" and "full of bugs".
  - *Carbon Engine* is free and FE-compatible, with mobile and Xbox support, stances, leaning and an installer plugin. A critic gave it 5.5/10 for milsim (bunnyhop while shooting, fast ADS movement). It is obfuscated.
  - *FE Gun Kit* suits custom animations, but "viewmodel is a hassle to setup with no official tutorials".
  - Consensus: none is ideal for serious games.
  - Sources: [DevForum: Best weapon systems…](https://devforum.roblox.com/t/what-are-the-best-weapon-systems-preferably-fe-for-a-game-with-a-lot-of-shooting/2716544); [DevForum: Usable fps frameworks?](https://devforum.roblox.com/t/is-there-any-usable-user-friendly-fps-frameworkssystems/2153442); [DevForum: Carbon Engine](https://devforum.roblox.com/t/ce-carbon-engine-revolutionary-fps-combat-technology/872472); [DevForum: Optimal Gun Kit](https://devforum.roblox.com/t/optimal-gun-kit/2137793) (search-summary; may be outdated)

### Inferences
- **Feel checklist (client, frame 0):**
  1. Play the fire animation, muzzle flash and a pooled tracer Beam/Part.
  2. Apply camera kick: spring on pitch/yaw added to the camera after the user's input so the player can counter it. Add separate high-frequency, low-amplitude visual shake on the viewmodel only.
  3. Show viewmodel recoil and sway springs, plus a reload/ADS animation.
  4. Play the shot sound layered with a distance tail. Pre-load sounds and pool Sound instances.
  5. Show an **optimistic hit marker** plus a hit sound when the local raycast hits a character, then upgrade to a confirmed marker, damage number and kill sound when the server acks.
  6. Show the kill feed and elimination banner only from the server.
  Use deterministic recoil patterns (learnable, more competitive) plus small random spread from a seed shared with the server so the angle validation in §1 works.
- Optimistic markers versus confirmed damage is the standard compromise. Count how often optimistic hits are rejected; a high rate signals tolerance problems or cheating.
- Under Server Authority, keep all of this in RenderStepped and prepare to undo mispredicted VFX, per the techniques doc.
- Rather than adopting ACS, Carbon or FE Gun Kit, fork the open Laser Tag / FPS System template code. It is unobfuscated, uses Roblox-recommended validation, and is being updated for Server Authority and Aim Assist.

## 5. Mobile/console controls (auto-fire, aim assist, layout, ContextActionService vs Input Action System) and fairness (input-based matchmaking)

### Takeaway
The **Input Action System (IAS)** is now fully released and is the intended cross-platform input layer. Roblox's default PlayerScripts were converted to IAS, and the old scripts are reportedly phased out by 2027. Server Authority requires `PlayerScriptsUseInputActionSystem`. IAS does **not** auto-create touch buttons the way `ContextActionService:BindAction(..., true)` did, so you must build the mobile HUD. Roblox ships an official **Aim Assist** module, auto-enabled on gamepad and touch in its FPS/Laser Tag templates. Roblox's server-join matchmaking has a **Device Type** signal, but that is for public-server placement. A queue-based 1v1–3v3 game must implement input-based pools itself.

### Cited Findings
- "The majority of Roblox sessions are played on mobile devices." Use `UserInputService.PreferredInput` to adapt UI. Mobile supports haptics, TouchSwipe/TouchPinch, accelerometer and gyroscope. The default orientation is `LandscapeSensor`. — [Roblox Docs: Mobile input](https://create.roblox.com/docs/input/mobile)
- IAS structure: `InputContext` (e.g. PlayContext, NavContext; `Priority`, `Sink`), then `InputAction` (Type Bool / Direction1D / Direction2D / Direction3D / ViewportPosition; events Pressed, Released, StateChanged; `PreferredBinding` tracks the current device), then `InputBinding` (KeyCode, `UIButton` for touch GuiButtons, `Scale`, `PressedThreshold` for analog triggers). Camera example: Direction2D with Thumbstick2, MouseDelta (Scale 0.01) and TouchDelta (Scale 0.01). — [Roblox Docs: Input Action System](https://create.roblox.com/docs/input/input-action-system)
- IAS full release (with converted PlayerScripts) added touch keycodes (`TouchPosition`, `TouchPinch`, `TouchDelta`) and a `UIModifier` property that extends modifier behavior to touch. A news account says old player scripts are phased out by 2027. An **Input Action Manager** (player rebinding) is in Studio Beta. — [DevForum: Full Release IAS](https://devforum.roblox.com/t/full-release-input-action-system-ias-newly-converted-player-scripts/4678416); [RoUtility on X](https://x.com/RoUtilityNews/status/2065136799790293135); [DevForum: Studio Beta Input Action Manager](https://devforum.roblox.com/t/studio-beta-input-action-manager/4737890) (search-summary)
- Migration gotcha: "the Input Action System does not generate that button for you". Replacing `BindAction` with InputAction silently removes the mobile control unless you add touch UI. — [simplified.media IAS guide (third party)](https://simplified.media/guides/roblox-input-actions)
- An engine bug report (Client Beta era) says IAS doesn't detect input-ended on mobile UI buttons. This matters for hold-to-fire, so verify it's fixed. — [DevForum: IAS not detecting input ended on mobile](https://devforum.roblox.com/t/issue-with-inputaction-system-not-detecting-input-ended-using-a-ui-button-on-mobile-devices/3897882)
- **Action slots** (Character Controller Library / Input Action Manager) are predefined slots with default KBM, gamepad and touch bindings: slot 1 = Space/ButtonA/touch ① (Jump), slot 2 = LeftShift… On mobile, slots 1–7 appear as on-screen buttons. Setting `ActionSlot = 0` picks the next free slot. Reconfiguration via the Input Action Manager is "in the future". — [Roblox Docs: CCL custom abilities (action slots include)](https://create.roblox.com/docs/characters/character-controller-library/custom-abilities)
- **Official Aim Assist:** the module ships in the FPS and Laser Tag templates and can be added to any experience. The API includes `AimAssist.new()` and `setType`. "AA is automatically turned on when players equip a weapon on gamepad or touch devices" and pulls toward the closest visible target while the camera moves. Posted about Nov 2025. — [DevForum: Get Aim Assist in Studio Templates](https://devforum.roblox.com/t/get-aim-assist-in-studio-templates-or-add-it-to-your-experience/4082644) (search-summary; friction/magnetism parameters not retrieved)
- Community resources: "Overhead Aim" (mobile shift-lock aiming with a virtual second cursor); threads on two-finger mobile aiming. — [DevForum: Overhead Aim](https://devforum.roblox.com/t/overhead-aim-mobile-aim-support-for-shiftlock-on-mobile/4179313); [DevForum: Aim with 2 fingers on mobile](https://devforum.roblox.com/t/how-do-i-allow-player-to-aim-with-2-fingers-on-mobile/4220085)
- **Matchmaking:** Roblox's configurable matchmaking has a "Player Device Type" attribute (Computer, mobile, tablet, console, VR) and a **Device Type signal**: ratio of players on the server with the same device as the joining player. Custom attributes and signals are also supported. — [Roblox Docs: Matchmaking attributes and signals](https://create.roblox.com/docs/matchmaking/attributes-and-signals)
- A community "Match" module provides configurable rules, ELO ranges, batching and teleport retries, but is not device-aware. — [DevForum: Match – Customizable Matchmaking Module](https://devforum.roblox.com/t/match-customizable-matchmaking-module/3985013)
- A gamepad input doc exists (`input/gamepad.md`) covering standard bindings; IAS bindings handle Thumbstick2 camera and analog triggers via PressedThreshold. — [Roblox Docs: Gamepad input](https://create.roblox.com/docs/input/gamepad); [Input Action System](https://create.roblox.com/docs/input/input-action-system)

### Inferences
- **Mobile layout recommendation (RIVALS-style shooter):**
  - Left thumb: dynamic thumbstick.
  - Right thumb: camera drag area, a large fire button reachable without lifting (plus an optional second fire button on the left for "claw" players), ADS toggle, reload, jump, and **2–3 ability buttons in an arc** for the drafted abilities.
  - All buttons repositionable and resizable, layout saved per player in DataStore.
  - Options: **auto-fire on target**, i.e. fire automatically when the crosshair raycast (or a slightly thickened spherecast) is on an enemy, a common mobile-shooter convention. Gate it so it can't out-DPS manual fire (apply weapon fire rate, require a short dwell).
  - Haptic tick on hit.
  - Use the official Aim Assist module on touch and gamepad: slowdown/friction near targets plus mild pull while moving. Never apply it to mouse.
- Bind every action in IAS with three bindings (KBM KeyCode, gamepad KeyCode, touch UIButton) and use `PreferredBinding` to swap button glyphs. Under Server Authority, read IAS state inside BindToSimulation for movement and abilities.
- **Fairness:** the built-in Device Type signal only affects which public server you land in. For queued 1v1–3v3, record `UserInputService.PreferredInput` (and a "touch-only" flag) at queue time. Run **input-based queues** (KBM pool versus touch+gamepad pool), or at least weight the MMR search, with an opt-in to cross-input. Gamepad players with aim assist arguably belong with touch. Also keep separate MMR per input pool or a per-input skill offset. Aim assist is the main fairness lever, so tune it so mobile/gamepad isn't strictly better at close range in small arenas.
- Aim assist is client-side. The server cannot tell AA-driven aim from a cheat, so AA strength must be modest and server heuristics must allow for the AA profile.

- No Roblox-provided input-based matchmaking for custom queues was found. MemoryStore-based queueing is assumed but was not researched here.

## 6. Ability systems: cooldowns, VFX replication, server validation

### Takeaway
DevForum consensus and Roblox's own patterns agree. **The server owns cooldowns and effect resolution. The client predicts instantly for responsiveness and UI.** VFX are replicated by the server telling clients to play them, never by the server creating them. New in 2026, Roblox's **Character Controller Library (CCL, beta)** defines abilities as deterministic Luau tables that run in *both* the predicted client simulation and the authoritative server simulation, with built-in timed cooldown labels. This is a strong fit for a drafted movement-ability kit.

### Cited Findings
- The server should start and own the cooldown timer; the client timer is "only a UI display". Client debounces can be bypassed because exploiters fire the remote directly. — [DevForum: Should abilities be managed on the server or the client?](https://devforum.roblox.com/t/should-abilities-be-managed-on-the-server-or-the-client/3073053); [DevForum: How to make secure cooldown for local script?](https://devforum.roblox.com/t/how-to-make-secure-cooldown-for-local-script/3674754) (search-summary)
- The prediction pattern: the client "predicts" everything from input and the server "performs the actual calculations and corrects the client if it's desynced". There is always some latency in syncing cooldown changes. — [DevForum: Handling Cooldowns and Player State in a Client–Server Combat System](https://devforum.roblox.com/t/handling-cooldowns-and-player-state-in-a-client%E2%80%93server-combat-system/4160241); [DevForum: Client side and server side cooldowns](https://devforum.roblox.com/t/client-side-and-server-side-cooldowns/871177) (search-summary)
- VFX: the server validates hits and tells clients to play victim VFX. Server-owned physics keeps VFX in sync but can make dashes and tweens stutter ("dashes with turning are a big no-no"). That thread predates Server Authority. — [DevForum: Ability Framework Replication Help (TSB-like)](https://devforum.roblox.com/t/ability-framework-replication-help-similar-to-the-strongest-battlegrounds/3034728) (search-summary)
- Replicate cooldown state with attributes, server-authoritative. — [DevForum: Does ability cooldown need to be done on client and server?](https://devforum.roblox.com/t/does-ability-cooldown-need-to-be-done-on-the-client-and-server/2024373) (search-summary)
- A community cooldown-management module exists. — [DevForum: [Cooldowns] Ultimate Cooldown/Debounce Management Module](https://devforum.roblox.com/t/cooldowns-the-ultimate-cooldowndebounce-management-module-system/3885782)
- **CCL (Roblox, beta):** a "modular framework for building character movement and behaviors through attributes and Luau scripts" that "replaces rigid `Humanoid` state machines". Opt in via File > Beta Features > "AvatarAbilities Character Controller Library", then Avatar Settings > Movement. — [Roblox Docs: Character Controller Library](https://create.roblox.com/docs/characters/character-controller-library)
- CCL custom ability example (Dash): `require("@rbx/AvatarAbilities")`; `StartsWhen = All(Sensor.Ground, Not("DashCooldown"))`; `TimedLabels.OnStart` broadcasts `DashWindow` for 0.2 s; `OnStop = { DashCooldown = 1.0 }` sets the cooldown. Registration must happen on the server, but "ability callbacks run in both the predicted client simulation and the authoritative server simulation. Keep callback behavior deterministic." Abilities bind to action slots (on mobile, slots 1–7 show as touch buttons). — [Roblox Docs: CCL custom abilities](https://create.roblox.com/docs/characters/character-controller-library/custom-abilities)
- Server Authority techniques for ability VFX: attribute-driven state machines rendered in RenderStepped, "undo" mispredicted effects, predictive instance creation for spawned projectiles, fuses/telegraphs to hide resimulation. — [Roblox Docs: Server authority techniques](https://create.roblox.com/docs/projects/server-authority/techniques)
- Laser Tag: the same cooldown runs on client and server, with the server as source of truth, plus a client cooldown bar. — [Roblox Docs: Implement blasters](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/implement-blasters)

### Inferences
- **Recommended ability architecture for a draft game:**
  1. A shared `AbilityDefinitions` ModuleScript per ability holding data (cooldown, charges, range, cast time, damage) plus pure functions (target validation, effect math).
  2. Server keeps an `AbilityState` per player: drafted loadout locked at draft end, `cooldownEndsAt` in server time, charges.
  3. The client presses the IAS action, checks its local cooldown mirror, plays the cast animation and VFX immediately, and sends `{abilityId, castId, aim params, clientServerTime}`.
  4. The server validates: ability is in the drafted loadout, cooldown elapsed (small grace, ~100 ms, for latency), alive and not stunned, range and LOS, rate-limit token bucket. Then it applies the effect and broadcasts `{casterId, abilityId, castId, params}` on a remote so other clients render VFX locally. On rejection it sends a correction (cooldown refund/reset, cancel VFX).
  5. Cooldown display is driven by server-replicated `cooldownEndsAt` attributes read against `GetServerTimeNow()`.
- **Movement abilities** (dash, blink, wall-run, double jump) should be CCL abilities or BindToSimulation code under Server Authority. They then predict smoothly and are server-validated for free, which avoids the classic "server-owned dash stutters" problem. Mind the 64-attribute and 50-character limits when storing state.
- **Damage and utility abilities** (grenades, turrets, heals, shields) follow the gun pipeline: client prediction for VFX, server resolution, and predictive instance creation for anything physical.
- Pool VFX instances on each client and replicate only IDs and parameters. Never `Clone` effects on the server into Workspace (bandwidth and latency). Use UnreliableRemoteEvent for purely cosmetic, frequent updates (≤1000 bytes).
- CCL is **beta** as of Oct 2026. Prototype with it, but keep a fallback (Humanoid plus custom BindToSimulation logic) until it is fully released.

### Gaps
- No official guidance found on CCL + Server Authority + IAS together in a shooter context. CCL beta stability and release timeline are unknown.
- No public info on how RIVALS or similar ability shooters replicate ability VFX.
