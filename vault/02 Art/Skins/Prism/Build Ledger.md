# Prism Vandal — milestone 1

## Scope and plan (2026-11-12)

Gameplay Studio place **133387545285290** only. Build `Vandal_Prism_v01` from `Vandal_RemasterV2_v05.blend`. Keep stock exports, geometry, UVs, rig, attachments, animation data and ammunition unchanged. The current Vandal has a shared atlas (256px raster check: zero inter-object overlap); reuse `tools/blender/bake_textures.py` with isolated output and restrained edge treatment.

1. Author lacquer Body/Panel and matte polymer in a versioned Blender copy; bake Color, Normal, Roughness and Metalness.
2. Clone the installed stock Studio model into `ReplicatedStorage.WeaponSkins.Prism.Vandal`; change appearance only. No mesh re-upload is required.
3. Add one Studio/gameplay-place-only session attribute, `PreviewSkinLine`, default Stock. Five choices: Stock, Prism, Redline, Nitrous, PopCircuit. Missing variants resolve to each weapon's stock template. Apply appearance in place to current/new held and world models without touching equip/loadout logic.
4. Playtest Stock → Prism → Stock, stock fallback, spawn/pickup-compatible cloning, idle, inspect, ADS and reload. Capture matching views and record exact limitations.

## Switching lines

In the gameplay Studio session: **F7** cycles Stock → Prism → Redline → Nitrous → PopCircuit; **Shift+F7** reverses. The server-owned `Workspace.PreviewSkinLine` attribute is the sole session setting. A fresh play session resets to Stock. The remote, service and controller are gated by `RunService:IsStudio()` **and** place ID 133387545285290. Published TestMode servers do not enable it.

Server applies surfaces to world models; clients apply to camera WorldModels. Appearance swaps clone preconfigured SurfaceAppearances and preserve animation state. Missing variants resolve to each gun's own stock template. Templates remain immutable; inventories, saved loadouts, lobby and live equip logic are untouched.
