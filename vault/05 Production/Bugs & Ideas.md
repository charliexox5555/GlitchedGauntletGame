- **2026-11-25, phone stick (owner: "you can pull it so far so then it just follows you and then if you try to slow down it ends up going backwards").** The stick base followed the thumb past 0.95× its ring, so easing back crossed the moved base and reversed. **Fixed:** the base stays where the thumb landed (RIVALS = Roblox's dynamic thumbstick, [study](../03%20Research/Rivals%20Reference/Mobile%20Controls.md)). Found on the way: `Humanoid.MoveDirection` is unit length, so any push ran at full speed (now the sim scales speed by the push); the stick was drawn 58 px under the thumb (`GetGuiInset` added to positions already in GUI space); `ModAltButton` fired twice when the camera-through setting was off. Studio-checked; real phone pending. [Mobile Controls](../02%20Art/UI%20Mobile%20Controls.md#stick-and-button-pass-2026-11-25)
- **2026-11-25, live error log + owner phone test ("really laggy at first", void until round 3, UI not scaled).** Text size was the phone's own setting. Fixed:
  - **TopBar resize loop** (~4,300 reports, "exponential deferred event growth ... fitShadow", TopBarController): `refit` set the `Fit` UIScale from the bar's own scaled width; pixel rounding nudged it every write, so on phones it never settled (lag, jumping UI). Now writes only past `SCALE_STEP` 1% / 2 px. Studio phone layout: 0 bar resizes in 8 s.
  - **Slow phones cancelled at 12 s** ("match load cancelled 12.5s ... all present clients timed out waiting for MatchReady", since V1204 / `READY_TIMEOUT` 30 → 12): `MatchPlan.allWaived` now waits `ALL_LOADING_TIMEOUT = 45 s`; `LOAD_CANCEL_TIMEOUT` 22 → 45. One late teammate still gets dealt in at 12 s.
  - **DuelsLoadingBlur parent locked** (~270): `MapLighting` captured and suspended other scripts' blurs, then `restore` re-parented the destroyed one and stopped half way. Script-owned blurs are skipped; re-parenting is guarded.
  - Still open, need the expanded rows: "Failed to load animation with sanitized ID" (305 server; the asset id), "Remote event invocation discarded" (96; the remote name). Known noise: `MoodAnimation` from players' avatars (R15Anim folder error), asset delivery/NetFail/HTTP 502, MovementGuard correction counts. TextFit loop (982) was capped 2026-11-24.
- **2026-11-25, scope orb (owner: "a faint orb and spot while scoped into the rifles").** Default Marshal / Outlaw / Operator scope pictures are clean (Studio test range). The leak was skins: hiding the viewmodel only set parts' `LocalTransparencyModifier`, so **Sundial** (solar light + motes, all three snipers) and **Riftforge** (Operator: core light, sparks, plasma beams) kept glowing in front of the scope; TempestStrike already hid its own. Also the **SHOW WHILE AIMING** crosshair drew its dot over the scope (ZIndex 3 vs 1). **Fixed in code:** `ViewmodelController` switches every Light / ParticleEmitter / Beam / Trail on a hidden gun off each frame and back on when it shows; `Crosshair.setScoped` keeps the crosshair off under the scope. Studio-checked 2026-11-25 (test mode, DevAim): scoped Sundial Marshal / Outlaw and Riftforge Operator show no enabled light, emitter or beam, and all come back after unscoping.
  - **Owner follow-up, the real cause:** "a small circle that has a reflection" in the middle of the gun, and Firewall / Frost Wall see-through while scoped. The snipers' `ScopeLens` was **Glass** material. Roblox still draws Glass at `LocalTransparencyModifier = 1` (the hide and the lens fade did nothing), and it doesn't draw see-through parts behind Glass, so the walls vanished inside the circle. Reproduced in Studio (a 55%-transparent test wall vanished inside a reflective circle at the scope's centre). **Fixed:** gun parts never wear Glass: SmoothPlastic, same colour, `Reflectance 0`, at the viewmodel build (`ViewmodelController`), the held third-person gun (`Weapon/WorldModel`) and skin re-applies (`SkinPreview.apply`). Verified: no circle, the wall shows through the scope. **Rule:** no Glass material on any gun or skin part (Studio templates still say Glass; the code overrides it).
